## 📌 프로젝트 개요

### 프로젝트 정의
**집-중 (Jip-joong)**: "내 집에 '집중'하는 시간, 내 '집'이 지어지는 '중'"

부동산 데이터 기반으로 현실적인 '내 집' 목표를 설정하고, **집 짓기 & 방 꾸미기** 게이미피케이션을 통해 저축 습관을 형성하는 금융 동기부여 플랫폼입니다.

### 핵심 컨셉
기존의 추상적인 "집나무 키우기"에서 **구체적이고 직관적인 "내 집 짓기"**로 전환하여:
- **Phase 1 (공사)**: 첫 마일스톤(10만원~100만원) 달성으로 빠른 성취감 제공
- **Phase 2 (인테리어)**: 가구 아이템 수집을 통한 장기적 동기 부여

### 차별점
1. **2025년 스트레스 DSR 3단계 규제 완전 반영** - 현실적 대출 한도 계산
2. **구매력 기반 맞춤 매물 추천** - 모든 매물이 아닌, 살 수 있는 매물만
3. **2단계 게이미피케이션 시스템** - 단기 목표(Phase 1) + 장기 목표(Phase 2)로 이탈 방지

### 대상 사용자
- **주 타겟**: 20대 후반 ~ 30대 초반 직장인
- **Pain Point**: "3억을 언제 모아?" 라는 막막함
- **Solution**: "일단 10만원 모아서 기초 공사부터" - 마이크로 목표 제시
- **연소득**: 3,000만원 ~ 6,000만원
- **목표**: 수도권 중소형 아파트 구매 (3억 ~ 5억)

## 🔄 핵심 UX 프로세스

이 서비스는 단일 루프가 아닌, **두 단계의 순차적 경험**을 제공합니다.

### Phase 1: 온보딩 & 첫 집 짓기 (Construction)

**목표**: 사용자 이탈 방지 및 '첫 성취감' 빠르게 제공

**프로세스**:
1. 회원가입 및 온보딩 (연소득, 희망 지역, 드림홈 설정)
2. **청사진 생성**: "OO님만의 집이 설계되었습니다"
3. **첫 마일스톤 설정**: 10만원~100만원 (사용자 선택 가능)
4. 저축 시작 → 공사 진행률 시각화
   - 0~20%: 터 닦기 & 안전 펜스
   - 20~50%: 골조(프레임) 공사
   - 50~80%: 외벽 & 지붕 공사
   - 100%: 완공!

**보상**: Phase 2 잠금 해제 (Grand Opening 연출)

---

### Phase 2: 메인 게임 & 꿈의 방 꾸미기 (Interior)

**목표**: 장기적인 저축 습관 유지 (Long-term Retention)

**프로세스**:
1. 3D 아이소메트릭 쇼룸 대시보드 제공
2. 월 저축 목표 달성 → 가구 아이템 획득
3. 가구 배치하여 나만의 방 꾸미기
4. 드림홈 목표까지 저축 지속

**보상**: 
- 기본 가구 (월 목표 달성)
- 레어 가구 (연속 저축 7일/30일/100일)
- 테마 컬렉션 완성 시 특별 효과

## 1. 회원 관리

### [P0] REQ-1.1 회원가입 및 로그인
**설명**: 이메일/비밀번호 기반 회원가입 및 JWT 인증 로그인  
**관련 테이블**: `users`

**입력**:
- 이메일, 비밀번호, 이름, 출생연도

**출력**:
- JWT 토큰 (Access Token + Refresh Token)
- 사용자 기본 정보

**제약조건**:
- 이메일 중복 불가
- 비밀번호 bcrypt 해싱
- Access Token 1시간, Refresh Token 14일

**구현 상태**: ✅ 완료 (`authStore.js`, `/login`, `/register`)

---

### [P0] REQ-1.2 온보딩 프로세스
**설명**: 신규 가입자의 연소득, 기존 대출, 희망 지역, **첫 마일스톤** 입력  
**관련 테이블**: `users`, `preferred_areas`

**입력**:
- Step 1: 출생연도
- Step 2: 연소득 (슬라이더, 2,000만원 ~ 1억원)
- Step 3: 기존 대출 월 상환액
- Step 4: 희망 지역 (시/도, 구/군, 최대 3개)

- `region_preference_metro` 자동 계산 (수도권 여부)
- `phase_status=BLUEPRINT` 설정
- **청사진 생성 화면 이동** (REQ-8.2)

**제약조건**:
- 온보딩 미완료 시 대시보드 접근 제한
- `preferred_areas`에 최대 3개 지역 등록

**구현 상태**: ⚠️ 부분 구현 (`/onboarding` 라우트 존재, Step 5 미구현)

## 2. 매물 조회

### [P0] REQ-2.1 구매력 기반 매물 필터링
**설명**: 사용자의 DSR 계산 결과 기반으로 실제 구매 가능한 매물만 표시  
**관련 테이블**: `properties`, `users`, `preferred_areas`, `dsr_calculations`

**입력**:
- 사용자 연소득, 기존 대출 월 상환액
- 희망 지역 (preferred_areas)

**출력**:

- 각 매물의 "구매력 대비 퍼센트" 표시

**제약조건**:
- 최대 대출 가능액 = DSR 계산 결과
- 필요 자기자본 = 매물가 - 최대 대출 가능액
- 계약금이 현실적 저축 범위 내인지 확인

**구현 상태**: ❌ 미구현 (`/properties` 라우트만 존재)

**제약조건**:
- `data_source`가 '국토부'인 매물 우선 표시

## 3. DSR 계산 시스템

### [P0] REQ-3.1 DSR 계산기
**설명**: 2025년 스트레스 DSR 3단계 규제를 완전 반영한 대출 가능액 계산  
**관련 테이블**: `dsr_calculations`, `policy_history`, `users`

**입력**:
- 연소득 (`annual_income`)
- 기존 대출 월 상환액 (`existing_loan_monthly`)
- 신규 대출 희망액 (`loan_amount`)
- 실제 금리 (`interest_rate`)
- 대출 기간 (`loan_period_years`)

**출력**:
- **월 상환액** (`monthly_payment`) - 원리금균등상환 방식
- **총 월 부채 상환액** (`total_monthly_debt`) = 기존 + 신규
- **DSR 비율** (`dsr_ratio`) = (월 상환액 × 12) / 연소득 × 100
- **최대 대출 가능액** (`max_loan_amount`)
- **승인 가능 여부** (`is_approved`) - DSR 40% 이하면 TRUE

**제약조건**:
- **스트레스 금리 자동 적용**:
  - 수도권: +1.5%
  - 비수도권: +0.75%
- `region_preference_metro` 기준 자동 판단
- 계산 이력 저장 (데이터 분석용)

**구현 상태**: ✅ 완료 (`dsrStore.js`)

---

### [P1] REQ-3.2 대출 상환 계획 시뮬레이션
**설명**: 원리금균등, 원금균등, 거치기간 등 다양한 상환 방식 비교  
**관련 테이블**: 없음 (계산만 수행)

**입력**:
- 대출 금액, 금리, 상환 방식, 거치기간

**출력**:
- 월별 상환 스케줄
- 총 이자 금액

**제약조건**:
- 거치기간 최대 1년

## 4. 드림홈 관리

### [P0] REQ-4.1 드림홈 설정
**설명**: 특정 매물을 "드림홈"으로 설정하고 저축 목표 자동 계산  
**관련 테이블**: `dream_homes`, `properties`

**입력**:
- 매물 ID (`property_id`)
- 목표 날짜 (`target_date`)

**출력**:
- 필요 계약금 (`target_amount` = 매물가 × 30%)
- 월 저축 목표 (`monthly_goal` = target_amount / 남은 개월 수)
- 예상 달성 가능 여부

**제약조건**:
- `is_current=TRUE`는 1명당 1개만 (UNIQUE 제약)
- 이전 드림홈은 `is_current=NULL`로 변경
- `status` = 'ACTIVE'

**구현 상태**: ⚠️ 부분 구현 (`dreamHomeStore.js`에 기본 로직)

---

### [P0] REQ-4.2 드림홈 달성률 조회
**설명**: 현재 저축액 대비 목표 달성률 표시, **Phase 진행률과 연동**  
**관련 테이블**: `dream_homes`, `saving_records`

**입력**:
- 사용자 ID (`user_id`)

**출력**:
- 목표 금액 (`target_amount`)
- 현재 저축액 (saving_records 합계)
- 달성률 (%)
- **Phase 1 달성률**: 첫 마일스톤 대비
- **Phase 2 달성률**: 드림홈 계약금 대비
- 예상 달성일 (`estimated_achievement_date`)
- 목표 대비 앞당김/늦어짐 일수 (`days_ahead_or_behind`)

**제약조건**:
- `is_current=TRUE`인 드림홈만 조회

**구현 상태**: ⚠️ 부분 구현 (`achievementRate` computed 속성 존재)

---

### [P1] REQ-4.3 드림홈 변경 이력 관리
**설명**: 드림홈 변경 시 이전 드림홈 보존 및 변경 사유 기록  
**관련 테이블**: `dream_homes`

**입력**:
- 새로운 매물 ID
- 변경 사유 (`deactivation_reason`)

**출력**:
- 이전 드림홈 히스토리

**제약조건**:
- `status` 변경: ACTIVE → CHANGED
- `deactivated_at` 기록
- 이전 드림홈은 `is_current=NULL`

**설명**: 첫 마일스톤 달성을 위한 공사 진행 게이미피케이션

## 🔒 비기능 요구사항

### 성능

**NFR-1: 응답 속도**
- API 응답 시간 < 300ms (95 percentile)
- 매물 리스트 조회 < 500ms
- DSR 계산 < 100ms

**NFR-2: 동시 사용자**
- 동시 접속자 1,000명 처리 가능
- TPS (Transaction Per Second) > 500

**NFR-3: 캐싱**
- 자주 조회되는 매물 정보 Redis 캐싱 (TTL: 24시간)
- 정책 정보 캐싱 (TTL: 7일)

**NFR-4: 애니메이션 성능**
- CSS 애니메이션 GPU 가속 (`transform: translateZ(0)`)
- 모바일에서 60fps 유지
- SVG 최적화 (SVGO), 초기 로딩 < 1.5초

---

### 보안

**NFR-5: 인증/인가**
- JWT 기반 인증 (Access Token + Refresh Token)
- HTTPS 필수
- SQL Injection, XSS 방어

**NFR-6: 개인정보 보호**
- 비밀번호 bcrypt 암호화 (salt rounds: 10)
- 민감 정보 (연소득) 암호화 저장
