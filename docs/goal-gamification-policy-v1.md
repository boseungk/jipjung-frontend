# 목표(드림홈) × 가상 집 성장(쇼룸/레벨) 정책 v1

## 0. 목적
- “목표 아파트 1개를 정하고, 저축을 이어가는 동안 **가상의 집이 빠르게 성장**해 동기를 부여”하는 컨셉을 **일관된 규칙/데이터/UX**로 정리한다.
- 목표 금액이 큰 현실을 고려해, “목표 진행률(%)”만으로 집이 변하는 느린 경험을 피하고 **XP 기반 성장 트랙**을 메인으로 둔다.

## 1. 배경(현재까지 대화 기반)
- 원래 컨셉: 목표(드림홈) 1개를 세우고, 그 목표를 향해 저축하면서 집이 성장(동기부여).
- 관찰: 목표 금액이 커서 목표 기반 단계 전환이 너무 느림.
- 방향 전환: 목표는 1개를 유지하되, **저축 활동으로 XP를 쌓아 집을 빠르게 성장**시키는 게이미피케이션을 강화.
- 추가 요구: 목표 100% 달성 이후에도 서비스 흐름이 끊기지 않아야 함.

## 2. 핵심 원칙(결정)
1) **드림홈(목표) 트랙**과 **가상 집 성장(레벨/XP) 트랙**은 분리한다.
2) 목표 100% 달성은 “엔딩/초기화”가 아니라 **마일스톤 이벤트**로 취급한다.
3) 목표 100% 달성 이후에도 사용자는 **같은 목표로 저축을 계속 기록(초과 저축)** 할 수 있어야 한다.
4) 목표 상향은 자동이 아니라, **달성 시점에 “상향 제안”을 제공하고 사용자가 선택**한다.

## 3. 용어
- **드림홈(Goal/DreamHome)**: 사용자가 선택한 목표 아파트 + 목표 금액/날짜/월 목표 등의 저축 목표.
- **가상 집 성장(Gamification/Showroom)**: 저축 활동으로 XP를 얻고 레벨/단계가 올라가며 시각화(집 짓기/인테리어)가 진행되는 트랙.
- **마일스톤(Milestone)**: 목표 달성(100%) 시점에 노출되는 축하/보상/다음 액션(목표 상향 제안).

## 4. UX 정책

### 4.1 목표 진행 중(<100%)
- 목표 카드: 저축액/목표/남은 금액/달성률 표시
- 저축(입금) 시:
  - 목표 저축액 증가
  - 자산 성장 차트 업데이트
  - XP 증가 → 가상 집 성장(레벨/집 단계/인테리어 단계) 반영

### 4.2 목표 달성 순간(=100% 도달)
- 축하 UI(토스트/모달/뱃지 등) 노출
- **“목표 상향 제안” 모달 노출**
  - 버튼 A: `목표 상향하기` (사용자 선택)
  - 버튼 B: `지금은 유지하기` (초과 저축 계속 가능)

### 4.3 목표 달성 이후(>=100%, 초과 저축)
- 목표 달성률은 100%로 고정 표시 가능
- 추가로 `초과달성 금액(= savedAmount - targetAmount)`을 노출하여 진행감을 유지
- CTA는 기본적으로 `목표 상향하기`를 제공 (언제든 사용자가 선택 가능)

## 5. 백엔드 정책(데이터/상태)

### 5.1 “현재 목표” 정의
- “현재 목표”는 다음 규칙으로 1개가 선택된다.
  1) `status = ACTIVE`가 있으면 그 목표가 현재 목표
  2) ACTIVE가 없으면 최근 `status = COMPLETED`를 현재 목표로 간주 (달성 이후 초과 저축/표시를 위해)

> 이 규칙은 “목표 달성 후에도 끊김 없이 계속 저축/표시”를 위해 필요하다.

### 5.2 상태(status) 의미(권장 해석)
- `ACTIVE`: 현재 목표 (진행 중 또는 달성 후 초과 저축 중)
- `COMPLETED`: 목표 금액 100%를 **최초로 넘긴 상태를 기록**하기 위한 마일스톤 상태
  - 단, COMPLETED라도 “현재 목표”로 간주될 수 있으며 저축 기록은 허용될 수 있다.

### 5.3 저축 기록 허용 규칙(필수)
- 저축 기록 API는 “현재 목표”에 대해 **status가 ACTIVE/COMPLETED 모두 허용**해야 한다.
- 목표 달성 후(COMPLETED)에도 `DEPOSIT` 기록이 가능해야 UX가 끊기지 않는다.

### 5.4 마일스톤(완료) 트리거 규칙(필수)
- 목표 달성 마일스톤 처리는 “매 요청마다 반복 실행”이 아니라, **최초 달성 순간(경계 통과)**에만 수행한다.
  - 예: `savedAmount`가 `targetAmount`를 최초로 넘었을 때만 `COMPLETED` 전환/컬렉션 등록/보상 지급.
  - 이후 초과 저축은 상태 전환 없이 진행.

## 6. API/응답 계약(구현에 필요한 최소 변경)

### 6.1 대시보드 응답(`/api/users/dashboard`)
- 목표 유무 판단 및 후속 액션을 위해 최소한 아래 필드가 필요:
  - `profile.userId` (프론트 로컬 저장 키/복원에 필요)
  - `goal.dreamHomeId` (목표 유무 판단에 필요)
  - (권장) `goal.isCompleted` (달성 시점 UX 트리거에 필요)

> 목표 상향 기능을 “기존 API(`/api/dream-home`) 재사용”으로 구현하려면 아래도 추가로 필요:
  - `goal.aptSeq`
  - `goal.targetDate`
  - `goal.monthlyGoal`
  - (선택) `goal.targetAmount`, `goal.savedAmount`는 이미 존재

### 6.2 목표 상향(업데이트) API
선택지 A(권장, 단순): 기존 `POST /api/dream-home` 재사용
- 프론트가 현재 목표의 `aptSeq`/`targetDate`/`monthlyGoal`을 알고 있어야 함(대시보드 응답 확장 필요)

선택지 B(대안): 전용 API 신설
- 예: `PATCH /api/dream-home/target`
  - body: `{ targetAmount, targetDate, monthlyGoal? }`
  - aptSeq는 서버가 현재 목표에서 가져옴
  - 장점: 프론트 요구 필드 감소, UX 단순화

## 7. 프론트 구현 체크리스트(시작점)

### 7.1 목표 카드/대시보드
- “목표 없음” 판단은 `dreamHomeId` 단일 값에만 의존하지 말고, `hasDreamHomeGoal`(gapAnalysis.hasTarget 등)로 보강.
- 달성 상태(`isCompleted`)이면 “목표 상향 제안” 모달 트리거:
  - 최초 1회만 노출(예: localStorage에 `goalMilestoneShown_{dreamHomeId}` 저장)
  - `지금은 유지하기` 선택 시: 초과 저축/100% 상태로 계속 표시

### 7.2 목표 상향 모달(UX)
- 입력/선택 항목(MVP):
  - 추천 상향 옵션(예: +5%, +10%, +20%) + “직접 입력”
  - 목표 달성일은 필수(백엔드 제약) → 기존 날짜 유지 or 추천(예: +6개월/+1년) 제공
- 성공 시:
  - 대시보드 재로딩 또는 store 동기화
  - 진행률/남은 금액 갱신

### 7.3 새로고침/복원(상태 지속성)
- 인테리어 진행도는 localStorage 키를 **token 기반이 아니라 userId 기반**으로 저장/복원하고, 레거시 키에서 자동 마이그레이션.

## 8. 백엔드 구현 체크리스트(시작점)

### 8.1 “현재 목표” 조회 공통화
- 대시보드/저축 기록 모두에서 동일한 “현재 목표” 규칙을 사용한다.
- 필요한 경우 Mapper에 `ACTIVE 우선, 없으면 최근 COMPLETED` 조회 쿼리를 추가한다.

### 8.2 저축 기록 허용
- 저축 기록 시 “현재 목표”가 COMPLETED여도 예외 없이 기록되도록 수정한다.
- 달성 마일스톤 처리(상태 전환/보상/컬렉션 등록)는 “최초 달성 순간”에만 수행한다.

### 8.3 대시보드 계약 확장(목표 상향 구현을 위해)
- `profile.userId`, `goal.dreamHomeId`는 필수
- 목표 상향에 기존 API를 재사용하려면 `goal.aptSeq`, `goal.targetDate`, `goal.monthlyGoal`을 포함한다.

## 9. 수용 기준(Acceptance Criteria)
1) 목표 달성 후 새로고침해도 대시보드에서 목표/자산차트/인테리어 진행도가 유지된다.
2) 목표 달성 후에도 저축 기록이 계속 가능하다(초과 저축).
3) 목표 달성 시 “목표 상향 제안”이 노출되며, 사용자가 선택해 목표 금액/날짜를 갱신할 수 있다.
4) “목표 없음” UI가 목표 설정/달성 상태에서 잘못 노출되지 않는다.
